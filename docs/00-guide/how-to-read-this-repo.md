# How to Read This Repository as a BA / System Analyst

| Question | Recommended artifact |
|---|---|
| Why is the system needed? | `01-business-overview/business-problem.md` |
| What should the project achieve? | `01-business-overview/project-objectives.md` |
| What is in scope? | `01-business-overview/project-scope.md` |
| Who uses or influences the system? | `01-business-overview/stakeholders.md` and `03-use-cases/actors.md` |
| What must the business/system support? | `02-requirements/` |
| What user interactions are documented? | `03-use-cases/` |
| How are interactions/design visualized? | `04-diagrams/` |
| What data entities are used? | `05-database/` |
| What was implemented visually? | `06-ui/` |
| How can behavior be accepted/tested? | `07-testing/` |
| What is ambiguous or incomplete? | `08-quality/known-gaps-and-inconsistencies.md` |

Recommended learning path:

**Business context -> Requirements -> UC07 Food Ordering -> Activity/Sequence Diagram -> Data Model -> UI -> UAT -> RTM.**

This path shows how a business need becomes a requirement, an interaction flow, a design model, and a testable acceptance scenario.
